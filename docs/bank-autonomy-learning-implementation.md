# نماء — عقد التنفيذ المالي (إصدار تأسيسي)

## حدود المنظومة
- البنك المركزي: تجميع مالي، مراقبة سيولة، تنبيهات ومقترحات موافقة؛ لا يملك رصيدًا إضافيًا عند تجميع الأرصدة الفرعية.
- الهلال: المدفوعات التشغيلية والالتزامات والبنود اليومية.
- ملاذ: الادخار والأهداف والطوارئ؛ يجب تحديد الحد المحمي من قبل المالك ولا يجوز افتراض أنه صفر في الإنتاج.
- أصول: تسجيل الأصول والمحافظ والاستثمار؛ لا يفتح صفقات دون موافقة صريحة.

## الصلاحيات
- روتين معتمد مسبقًا: تصنيف، إشعار، احتساب، تحديث تقرير؛ يسمح بالتنفيذ الآلي بعد نشر سياسات مختبرة.
- قرارات محمية: سلفة، تحويل بين البنوك، استثمار، توزيع راتب، تعديل سياسة؛ موافقة مالك مسجلة قبل التنفيذ.
- التنفيذ البنكي الحقيقي يحتاج مزودًا مخولًا وآليات تحقق ومطابقة منفصلة. اعتماد القرار لا يثبت حصول التحويل.

## التعلم
1. تخزين المثال المصحح مع هوية البنك والبند والتصنيف والسياق.
2. اكتشاف تكرار التصنيفات مع حد عينات واتساق قابلين للضبط.
3. إنشاء اقتراح غير نافذ؛ يعرض الأمثلة وتبرير الاقتراح.
4. لا تصبح القاعدة فعالة إلا بموافقة المالك وتحديد مدى انطباقها واستثناءاتها.
5. حفظ نسخة القاعدة وسجل التصحيحات وإمكانية التعطيل والتراجع.

## مخطط قاعدة البيانات المطلوب قبل الربط
- bank_policies: owner_id, bank_id, version, protected_minimum, liquidity_threshold, active, approved_at
- bank_categories: owner_id, bank_id, category_key, limit_amount, automation_scope
- financial_decision_requests: owner_id, bank_id, kind, amount, status, reason, approver, approved_at, executed_at, idempotency_key
- behavior_examples: owner_id, bank_id, merchant_key, category, outcome, corrected, occurred_at
- learning_proposals: owner_id, bank_id, evidence_count, consistency, suggested_category, status
- internal_loans: debtor_bank, creditor_bank, principal, interest_policy, repayment_schedule, status
- audit_events: owner_id, entity_type, entity_id, action, prior_state, next_state, occurred_at

All monetary values are minor units (halalas); enforce ownership authorization and referential integrity in the database.

## ضوابط الواجهة
- اللغة عربية واتجاه RTL؛ عرض الأرقام 0-9 ورمز الريال السعودي الجديد من خط معتمد يدعمه.
- الهوية المعتمدة لنماء فقط، دون إدخال ألوان أو خطوط افتراضية من تصور الصور.
- الأولوية للجوال؛ صفحات مستقلة لكل بنك وبنوده؛ شاشة مستقلة للموافقات وسجل التعلم.

## بوابة الجودة قبل الدمج أو النشر
1. مراجعة المخطط الحالي وربط الملكية والتحقق من الهويات.
2. اختبارات الحسابات الدقيقة ورفض المعاملات المكررة ومطابقة القيود الثنائية.
3. اختبار صفر تجاوز للصلاحيات والاحتياطي المحمي.
4. اختبار صلاحيات كل بنك والبند، ومراجعة التدقيق والتراجع.
5. تشغيل typecheck و vitest وبناء Vercel في بيئة غير إنتاجية.
6. عدم نشر أو دمج إلى فرع الإنتاج دون تفويض مستقل من المالك.

## حالة التنفيذ
تم إنشاء نواة حسابية مستقلة واختبارات مصدرية في فرع تطوير. لم تُربط بعد بقاعدة البيانات أو الواجهة، ولم تُشغّل الاختبارات عبر بيئة تنفيذ متصلة بالمستودع. لا يُعد هذا تسليمًا مكتملًا.
