04 — دليل العمليات والآليات والخوارزميات التشغيلية لبنك الأصول
الحالة: نسخة نهائية منسقة للمراجعة والاعتماد
المرجع التأسيسي: AIB-39 وAIB-54 إلى AIB-81 ومسار AIB-INV، مع الإحالات الحاكمة إلى الملفات 01 و02 و03 و05 و06.
1. الغرض والنطاق التشغيلي
يحوّل هذا الدليل سياسات بنك الأصول إلى مسارات تشغيل وخوارزميات وحالات قابلة للتنفيذ والتتبع وإعادة الإنتاج. يملك الملف 04 المعادلات والمحركات والتنفيذ وسجل التشغيل، بينما يملك الملف 06 السياسات والنطاقات والقيود. عند التعارض تتقدم السياسة ويوقف التنفيذ.
العمليات الأساسية تشمل: استقبال الفرص والمبالغ، جمع البيانات وتشغيل بوابة البيانات (Data Gate)، التحليل المتخصص، فحص الملاءمة، بناء التوصية، AUTHORITY_GATE، التنفيذ، المتابعة، إعادة التقييم، إعادة التوازن، معالجة الأهداف، تحديث أوضاع البنك، المحاسبة، الرسوم، دورة حياة المنتج، والإغلاق والتسييل.
2. مخطط الحالات (State Machine) الأساسية
المسار العام الموحد هو:
RECEIVED → DATA_COLLECTION → DATA_GATE → ANALYSIS → SUITABILITY → RECOMMENDATION → AUTHORITY_GATE → USER_ACTION_REQUEST → WAITING_USER_CONFIRMATION → EXECUTION_EVIDENCE → VERIFICATION → VERIFIED_EXECUTION → MONITORING → REASSESSMENT → AUDIT.
بعد AUTHORITY_GATE قد يظهر مسار مشروط قبل التنفيذ مثل MANAGER_REVIEW أو GOVERNANCE_ESCALATION أو WAITING_USER أو RISK_BLOCK. أما AUTO_AUTHORIZED فلا يعني التنفيذ المالي؛ بل يعني اعتماد القرار خوارزميًا داخل التفويض ثم الانتقال إلى USER_ACTION_REQUEST وانتظار المستخدم حتى يؤكد أنه نفذ الفعل ويقدم الإثبات المطلوب، وبعد التحقق فقط تسجل الحالة VERIFIED_EXECUTION.
أي مرحلة تستطيع إيقاف المسار عند نقص بيانات جوهرية، تعارض سياسة، خرق Hard Guard، أو خروج القرار عن التفويض.
3. المسارات الفرعية حسب نوع الأداة
توجد مخطط الحالات (State Machine) أساسية موحدة مع فروع متخصصة، ولا تنشأ مخطط الحالات (State Machine) مستقلة لكل أداة.
• السهم: MARKET_CHECK + PRICE_VALIDATION.
• الصندوق المفتوح: NAV_CHECK + REDEMPTION_RULES.
• الصندوق المغلق: LOCKUP_CHECK + EXTENSION_RULES + EXIT_PLAN.
• الصكوك: YIELD_CHECK + MATURITY_CHECK.
• الوديعة: RATE_CHECK + MATURITY_CHECK.
• العقار: VALUATION + LEGAL_CHECK + LIQUIDITY_CHECK.
• الملكية الخاصة: DUE_DILIGENCE + VALUATION + LOCKUP_CHECK.
• أدوات R4/R5: STRESS_TEST + SCENARIO_ANALYSIS.
4. صلاحية التوصية — RECOMMENDATION_VALIDITY_PARAMETER_SET
لكل توصية صلاحية زمنية وسعرية أو تقييمية، وتنتهي بأول Trigger نافذ من مجموعة الصلاحية أو عند تغير جوهري في البيانات أو السياسة أو فئة الاستقرار أو حالة البنك أو ظهور Hard Guard.
قيم الصلاحية حسب الأداة تحفظ في RECOMMENDATION_VALIDITY_PARAMETER_SET ذي إصدار، وليست حقائق أبدية. القيم التشغيلية الحالية تشمل أمثلة مثل: الأسهم المدرجة، الصناديق، الصكوك، العقار، الملكية الخاصة، الفرص التكتيكية، إعادة التوازن، والتوزيعات النقدية، ولكل منها نافذة زمنية وحد تغير مناسب لطبيعتها.
عند انتهاء التوصية:
• الانتهاء الزمني فقط دون تغير جوهري → REVALIDATION.
• تجاوز سعري أو تغير بيانات أو سياسة أو مخاطر أو MATERIAL_EVENT → FULL_REANALYSIS.
• خرق Hard Guard → إلغاء فوري للتوصية وعدم التنفيذ.
REVALIDATION هو تحقق مختصر من استمرار صلاحية البيانات والسعر والسياسة والملاءمة. FULL_REANALYSIS إعادة تحليل كاملة عندما تصبح الفرضيات الأصلية غير صالحة.
5. الأحداث الجوهرية — MATERIAL_EVENT_THRESHOLD_SET
إعادة التقييم الفوري تعمل عند تجاوز Trigger نافذ أو تحقق حدث حرج. تشمل المؤشرات الأساسية:
• LIQUIDITY_DROP_TRIGGER.
• هبوط السيولة تحت الحد الأدنى الإلزامي.
• INCOME_CHANGE_TRIGGER.
• NEW_OBLIGATION_MATERIALITY_TRIGGER.
• ELIGIBLE_CAPITAL_CHANGE_TRIGGER.
• تغير فئة الاستقرار.
• عبور هدف إلى NEAR_GOAL_THRESHOLD أو تغير أفقه جوهريًا.
• ASSET_PRICE_CHANGE_TRIGGER بحسب فئة الأداة.
• خرق Hard Guard.
• تغير حالة البنك.
• MARKET_RISK_CHANGE_TRIGGER.
• ظهور خطر جوهري.
التغيرات دون العتبات النافذة تبقى للمراجعة الدورية ما لم يظهر محفّز (Trigger) آخر. تحفظ العتبات التشغيلية كمعاملات ذات إصدار (Versioned Parameters) ولا تعامل كنسب عالمية ثابتة، مع استثناء العتبات التي يثبتها الملف 06 بوصفها سياسة حاكمة. في هذه الحالة يجوز لمجموعة عتبات الأحداث الجوهرية (MATERIAL_EVENT_THRESHOLD_SET) إضافة محفزات أشد تحفظًا أو إضافية، ولا يجوز لها إضعاف العتبة الحاكمة أو رفعها دون تغيير سياسة معتمد.

7. AUTHORITY_GATE والاعتماد الخوارزمي ومسار التنفيذ البشري
AUTHORITY_GATE هو نقطة الربط بين التحليل والتنفيذ. يقرأ نوع القرار، أثره، حدود التفويض، ووسوم USER_ONLY وMATERIAL_DECISION وHard Guard ثم يعيد أحد المسارات:
• AUTO_AUTHORIZED.
• MANAGER_REVIEW.
• GOVERNANCE_ESCALATION.
• WAITING_USER.
• RISK_BLOCK.
يسمح بالاعتماد الخوارزمي AUTO_AUTHORIZED فقط إذا اجتاز القرار بوابة البيانات (Data Gate) وHard Guards والسيولة وPolicy Bands والمخاطر وحدود التفويض، ولم يكن USER_ONLY أو قرارًا ماديًا يحتاج اعتمادًا أعلى. هذا الاعتماد لا يحرك الأموال ولا يغير الواقع المالي؛ بل ينشئ USER_ACTION_REQUEST للمستخدم.
أمثلة القرارات التي قد تصبح AUTO_AUTHORIZED وفق AUTHORITY_MATRIX: توصية توجيه توزيعات نقدية عبر مركز التخصيص، توصية إعادة توازن روتينية، توصية استعادة سيولة استثمارية، تصحيح مخالفة مرنة داخل CORRECTION_ENVELOPE، معالجة أداة مستحقة بعد إعادة الأهلية والملاءمة، توصية التعامل مع الأرباح، أو إعادة استثمار العوائد. جميعها تبقى قرارات/توصيات داخل المنصة وتنتقل إلى المستخدم عند الحاجة لحركة مالية.
لا يسمح للاعتماد الخوارزمي بتغيير Policy Band أو Hard Guard أو فئة الاستقرار، ولا بمنح DOCUMENTED_EXCEPTION دون مساره، ولا بحسم قرار USER_ONLY، ولا بتجاوز MATERIAL_DECISION_THRESHOLD أو حدود التفويض.
8. التعرف الآلي على المنتجات
المسار المعتمد:
تعريف المنتج (Product Identification) → تصنيف المنتج (Product Classification) → تطبيق السياسة (Policy Application).
يعتمد PRODUCT_PROFILE على خصائص المنتج الفعلية: نوع الأصل، التنويع والتركيز، الجهة أو المدير، الجغرافيا، العملة، السيولة، قيود الاسترداد، الرسوم، المخاطر، الرافعة المالية، الحجز والاستحقاق.
التصنيف لا يعني الاعتماد. بعد التصنيف تمر الأداة ببوابة البيانات والملاءمة والسياسة. عند نقص بيانات جوهرية تكون الحالة PRODUCT_DATA_INCOMPLETE ويتوقف القرار النهائي.
8.1 واجهة محفظة الاحتياطي المستثمر (Invested Reserve Portfolio)
عند إحالة بنك ملاءة جزءًا من الاحتياطي للاستثمار، يستخدم بنك الأصول مسارًا مستقلًا عن التخصيص الاستثماري الحر:
تفويض ملاءة (MALAA_RESERVE_MANDATE) → التحقق من المبلغ وحد السيولة وأفق الاسترداد → تصفية المنتجات بحسب سياسة ملاءة → تحليل الاستثمار والسيولة والمخاطر → بوابة الصلاحيات (AUTHORITY_GATE) → USER_ACTION_REQUEST → تنفيذ المستخدم → الإثبات والتحقق → المراقبة → الاستدعاء أو الاسترداد بطلب للمستخدم → التسوية والتدقيق.
لا تمر هذه الأموال عبر محركات النمو أو الفرص أو محافظ الأهداف، ولا تدخل في مقام 100% لرأس المال المؤهل لبنك الأصول. المنتج المؤهل يجب أن يحقق معًا شروط بنك ملاءة وشروط المنتج والسيولة والمخاطر في بنك الأصول؛ وعند التعارض يطبق الشرط الأكثر تحفظًا.
يعامل طلب الاستدعاء الصحيح الصادر من بنك ملاءة كأولوية حماية. يمنع الشراء الجديد من هذه المحفظة فورًا عند الاستدعاء، وتنفذ خطة الاسترداد بحسب آجال السيولة والقيود التعاقدية دون تأخير بقصد تحسين العائد.
9. محرك التخصيص التكيفي المقيّد — BOUNDED_ADAPTIVE_ALLOCATION
المبدأ: الذكاء يختار ويتعلم داخل حدود محكومة، ولا يملك حرية تحويل المبلغ إلى أصل أو سوق بلا قيود.
المسار الإلزامي للمبلغ الجديد:
INCOMING_CAPITAL → PROTECTION_AND_RESERVE_GATE → INVESTABLE_AMOUNT → ENGINE_BANDS → ASSET_CLASS_BANDS → MARKET_GEOGRAPHY_BANDS → PRODUCT_RANKING → TRANCHE_PLAN → CONSTRAINT_CHECK → USER_ACTION_REQUEST → VERIFIED_EXECUTION → MONITORING → LEARNING.
القواعد:
1) PROTECTION_AND_RESERVE_GATE يحدد أولًا ما يبقى للحماية والاحتياطي وما يصبح مؤهلًا للاستثمار.
2) ENGINE_BANDS يوزع الجزء الاستثماري بين السيولة الاستثمارية والدخل والنمو والفرص ومحافظ الأهداف داخل حدود الملف 06.
3) ASSET_CLASS_BANDS يحدد Min/Target/Max لكل فئة أصل مؤهلة حيث تكون السياسة قد عرّفت ذلك.
4) MARKET_GEOGRAPHY_BANDS يطبق قيود السوق والجغرافيا والعملة قبل اختيار المنتجات الفردية.
5) PRODUCT_RANKING يرتب المنتجات المؤهلة فقط بعد استبعاد ما يفشل البيانات أو السيولة أو التركيز أو المخاطر أو التكلفة أو الملاءمة.
6) الدرجة الذكية تحدد الموقع داخل النطاق ولا تمنح وزنًا مفتوحًا.
7) يجوز الاحتفاظ بجزء من المبلغ كسيولة استثمارية إذا لم توجد فرص مؤهلة كافية.
8) كل نتيجة تسجل البيانات والبدائل وأسباب الاستبعاد والأوزان قبل وبعد القيود وخطة الدفعات وسبب اختيار كل منتج.
عندما يكون المستوى ذا نطاق خطي:
RAW_TARGET = Band_Min + (Normalized_Score ÷ 100) × (Band_Max − Band_Min).
الوزن النهائي القابل للتنفيذ يخضع لأصغر سقف نافذ من Policy Band وRISK_CLASS_BAND وCOMBINED_HIGH_RISK_BAND وحدود المحرك والمصدر والقطاع والجغرافيا والعملة والسيولة والمخاطر والجدوى الاقتصادية.
إذا تعذر الوصول إلى توزيع مجموعه 100% من رأس المال المؤهل داخل بنك الأصول، تنتج الحالة ALLOCATION_CONSTRAINT_CONFLICT ويوقف التنفيذ؛ لا تغلق الخوارزمية الفرق اعتباطيًا.
10. الحد الاقتصادي — E_min
E_min ليس مبلغًا ثابتًا عامًا. PRODUCT_E_MIN هو أصغر تخصيص A يحقق معًا:
• A ≥ PRODUCT_MINIMUM.
• A ≥ MIN_TRADABLE_AMOUNT أو الحد الأدنى للوحدة أو الصفقة.
• عدم خرق حدود المصدر أو القطاع أو المنتج.
• عدم خفض السيولة دون الحد الإلزامي.
• EFFECTIVE_COST_RATE(A,H) = TOTAL_EXPECTED_COST(A,H) ÷ A ضمن MAX_TOTAL_COST_RATE النافذ.
TOTAL_EXPECTED_COST يشمل الرسوم الثابتة والمتغيرة، التنفيذ، الدخول والخروج، التحويل، وأي تكلفة قابلة للحساب. لا تستخدم عوائد متوقعة متفائلة لتبرير E_min.
الحد الاقتصادي للمحرك (ENGINE_E_MIN) هو أقل رأس مال يسمح بتكوين المحرك من منتجات مؤهلة مع احترام الحد الاقتصادي للمنتج (PRODUCT_E_MIN) والتنويع والسيولة ونطاق السياسة (Policy Band). إذا لم توجد قيمة قابلة للحل تنتج حالة عدم جدوى الحد الاقتصادي (ECONOMIC_MINIMUM_NOT_FEASIBLE) ويمنع الفتح. وعند استخدام الرمز E_min في مصفوفة رأس المال الصغير بالملف 06، يقرأ باعتباره مرجع جدوى مشتقًا من PRODUCT_E_MIN وENGINE_E_MIN بحسب المنتج والمحرك المرشح، وليس رقمًا عالميًا موحدًا.
11. السيولة الإلزامية — REQUIRED_LIQUIDITY_MONTHS
المدخل الأول هو Policy Band في الملف 06: مستقر جدًا 3–6 أشهر، مستقر 4–6، هش 6–9، حرج 9–12.
LIQUIDITY_PRESSURE_SCORE من 0 إلى 100 ويحسب من:
25% مخاطر استقرار الدخل + 20% تقلب المصروفات الأساسية + 20% ضغط توقيت الالتزامات + 15% قرب الأهداف المحمية + 10% صعوبة الوصول إلى السيولة + 10% ضعف قدرة التعافي.
كل عامل يحول إلى 0–100 بواسطة جداول Versioned. لا يسمح بدرجات وصفية حرة.
REQUIRED_LIQUIDITY_MONTHS_RAW = Band_Min + (LIQUIDITY_PRESSURE_SCORE ÷ 100) × (Band_Max − Band_Min).
REQUIRED_LIQUIDITY_MONTHS = Clamp(RoundTo0.5(REQUIRED_LIQUIDITY_MONTHS_RAW), Band_Min, Band_Max).
لا يعاد خصم مبالغ الالتزامات أو الأهداف القريبة في هذه المعادلة لأنها خصمت عند حساب رأس المال المؤهل؛ تستخدم خصائصها الزمنية والمخاطرية فقط لمنع الازدواج.
12. معامل السيولة — LIQUIDITY_FACTOR
LIQUIDITY_FACTOR(asset,horizon) قيمة بين 0 و1 تقيس ما يمكن اعتباره سيولة معدلة بالنسبة لأفق حاجة محدد.
LIQUIDITY_QUALITY_SCORE = 35% Access_Score + 20% Redemption_Score + 15% Market_Depth_Score + 15% Exit_Cost_Score + 15% Liquidation_Volatility_Score.
إذا تعذر الاسترداد أو التسييل قبل نهاية horizon أو تجاوزت فترة الحجز (Lock-up) أفق الحاجة بلا سوق خروج عملي، فإن LIQUIDITY_FACTOR = 0 كـ بوابة صارمة (Hard Gate). خلاف ذلك يكون العامل = LIQUIDITY_QUALITY_SCORE ÷ 100 مع Clamp بين 0 و1.
مرتكزات الإصدار التشغيلي الأول لـ Access_Score وRedemption_Score وMarket_Depth_Score وجداول Exit_Cost وLiquidation_Volatility تعد معاملات ذات إصدار (Versioned Parameters) قابلة للمراجعة وفق الملف 05.
السيولة المعدلة للأصل عند أفق h = قيمة الأصل × LIQUIDITY_FACTOR(asset,h). ولا تجمع القيم عبر آفاق مختلفة بوصفها سيولة واحدة؛ يحسب Coverage لكل أفق على حدة.

TRANCHE_TARGET_i يبدأ من 1÷N ويسمح بتعديل تكيفي داخل ±10 نقاط مئوية من الحصة المتساوية، بشرط أن يكون مجموع الحصص 100% وألا تقل أي دفعة عن PRODUCT_E_MIN أو الحد الأدنى القابل للتنفيذ. إذا صار التقسيم غير اقتصادي يخفض N حتى يصبح صالحًا.
لا تنفذ الدفعة التالية إلا إذا بقيت التوصية صالحة أو اجتازت REVALIDATION، ولم يظهر MATERIAL_EVENT أو Hard Guard، وبقيت السيولة والحدود سليمة. التوقيت مدفوع بالأحداث (Event-Driven) وليس مجرد مرور أيام ثابتة.
14. تعريف الدورة الناجحة — SUCCESSFUL_CYCLE
تعد الدورة ناجحة فقط إذا انتهت المدة المعتمدة دون Hard Guard breach أو MATERIAL_EVENT غير معالج، وكانت LIQUIDITY_COVERAGE_MONTHS عند أو فوق REQUIRED_LIQUIDITY_MONTHS لكل أفق مطلوب، وكانت البيانات الحرجة صالحة، ولم توجد مخالفة تركيز أو Policy Band غير معالجة، ونفذت الالتزامات وخطط التصحيح المستحقة. مرور الزمن وحده لا ينشئ SUCCESSFUL_CYCLE.
15. حلقة التعلم المستمر — LEARNING LOOP
بعد كل تنفيذ أو دورة يسجل المتوقع مقابل الفعلي (Expected vs Actual) في: العائد المعدل بالمخاطر، الانحراف عن Target، تكلفة التنفيذ، الانزلاق السعري (Slippage)، زمن الوصول للنقد، تكلفة الخروج، جودة التوقيت، تحقق سيناريوهات المخاطر، أثر القرار على الأهداف، ونجاح الدفعات.
طبقتا التعلم:
• التكيّف الفوري (Online Adaptation) داخل Envelopes معتمدة لتحديث Ranking وTiming Calibration داخل الحدود مع سقف حركة وتسجيل Version.
• تحديث النموذج (Model Update) لتغيير الأوزان أو البنية أو الحدود؛ لا يدخل الإنتاج مباشرة بل يمر بالاختبار والمقارنة مع خط الأساس (Baseline) ووضع الظل (Shadow Mode) ومسار الملف 05.
أي تعلم يقترح تغييرًا خارج الحدود يولد MODEL_CHANGE_PROPOSAL. لا يجوز للتعلم تعديل Hard Guards أو Policy Bands أو AUTHORITY_MATRIX أو تعريف رأس المال المؤهل مباشرة.
كل ناتج خوارزمي يسجل ALGORITHM_VERSION وMODEL_VERSION وPARAMETER_VERSION وPOLICY_VERSION وDATA_SNAPSHOT_ID والبيانات وسبب القرار وExpected Outcome. أي تدهور جوهري مقابل خط الأساس (Baseline) يفعل MODEL_ROLLBACK أو يوقف التكيف حتى المراجعة.
16. حوكمة المعاملات
جميع الأوزان والعتبات التشغيلية داخل LIQUIDITY_PRESSURE_SCORE وLIQUIDITY_FACTOR وEXECUTION_TIMING_RISK_SCORE وصلاحية التوصيات وSTATE_SLA وحدود الاعتماد الخوارزمي ونطاقات المعايرة تحفظ كـ PARAMETER_SET_VERSIONED.
التعلم قد يحسن التقدير والترتيب والتوقيت داخل الحدود فقط. تغيير وزن حاكم أو نطاق (Band) أو قاعدة صارمة (Hard Guard) أو صلاحية يحتاج طلب تغيير (Change Request) واعتمادًا وإصدارًا جديدًا وفق الملف 05. وأي رقم يعرّفه الملف 06 صراحة كحد سياسة حاكم — مثل حدود تغير الأوزان، الحد الأقصى للتعديل التكتيكي، مدد أو مراحل فتح محرك الفرص، أو عتبات سياسة محددة — لا يعامل كمعامل تشغيلي حر داخل الملف 04؛ يمكن للمعامل التشغيلي أن يكون أشد تحفظًا فقط ما لم يصدر تغيير سياسة رسمي.
17. إعادة التوازن — REBALANCING_ENGINE
يبدأ التوازن من الأعلى إلى الأدنى: الحماية والسيولة → المحركات → فئات الأصول → الأسواق → المنتجات.
ترتيب المعالجة:
NEW_CASH_FIRST → INCOME_REDIRECTION → BUY_UNDERWEIGHT → SELL_OVERWEIGHT.
لا يبيع النظام أصلًا جيدًا لمجرد انحراف بسيط إذا أمكن تصحيح الوزن بالتدفقات الجديدة أو التوزيعات. يصبح البيع خيارًا عند بقاء الخلل أو وجود خطر جوهري أو خرق حد.
SELL_PRIORITY_SCORE يراعي حاجة السيولة، الانحراف عن Target، التركيز، تدهور أطروحة الأصل، تكلفة الخروج، السيولة، أثر البيع على الهدف، البدائل، والمخاطر.
أسباب البيع تسجل بأكواد مثل PORTFOLIO_WEIGHT_DRIFT وCONCENTRATION_REDUCTION وASSET_THESIS_DETERIORATION وLIQUIDITY_NEED وGOAL_NEED وRISK_REDUCTION وSTRATEGIC_REALLOCATION وTACTICAL_REALLOCATION وPRODUCT_MATURITY_OR_EXPIRY وFEE_OR_ECONOMIC_EFFICIENCY وPOLICY_OR_HARD_GUARD وBETTER_ALTERNATIVE.
18. المحاسبة الاستثمارية — INVESTMENT_ACCOUNTING_LEDGER
يسجل النظام لكل أصل ومحرك ومحفظة بصورة منفصلة: CONTRIBUTED_PRINCIPAL وCOST_BASIS وMARKET_VALUE وUNREALIZED_PNL وREALIZED_PNL وCASH_DISTRIBUTIONS وFEES_AND_COSTS وNET_CASH_FLOW والتحويلات بين المحركات.
لا يعامل ارتفاع القيمة السوقية كسيولة أو ربح محقق. ولا تعد التوزيعات رأسمالًا جديدًا قبل مرورها بمركز التخصيص. التحويل الداخلي لا ينشئ ربحًا أو خسارة بذاته.
تسجل أصول محفظة الاحتياطي المستثمر (Invested Reserve Portfolio) في دفتر فرعي مستقل يثبت أن المالك الوظيفي هو بنك ملاءة وأن بنك الأصول جهة تنفيذ وإدارة استثمار فقط. لا تدمج قيمتها أو أرباحها أو خسائرها مع رأس المال المؤهل الحر أو أداء محركات النمو والفرص. عند الاسترداد تعاد الأموال والعوائد المستحقة إلى بنك ملاءة وفق التفويض، لا إلى مركز التخصيص العام لبنك الأصول.
معادلة التسوية:
ENDING_NAV = BEGINNING_NAV + NET_EXTERNAL_FLOWS + INVESTMENT_INCOME + REALIZED_PNL + UNREALIZED_PNL − FEES_AND_COSTS.
لا تدخل عمليات الشراء والبيع الداخلية كتدفقات خارجية، ولا تحتسب التوزيعات مرتين. أي فرق غير مفسر ينتج ACCOUNTING_RECONCILIATION_ERROR ويوقف الاعتماد المحاسبي حتى المعالجة.
19. الرسوم والتكاليف — FEE_AND_COST_ENGINE
يحسب قبل التنفيذ TOTAL_EXPECTED_COST وبعده ACTUAL_COST. تشمل الرسوم: شراء وبيع، فروق أسعار، إدارة، أداء، حفظ أو منصة، تحويل، عملة، خروج، وأي تكلفة دورية أو نظامية قابلة للقياس.
يفصل ONE_TIME_COST عن RECURRING_COST وEXIT_COST. تدخل التكاليف في E_min وPRODUCT_RANKING وإعادة التوازن. إذا جعلت الرسوم المنتج غير اقتصادي عند الحجم الفعلي تنتج COST_EFFICIENCY_FAIL.
التعلم يقارن EXPECTED_COST بـ ACTUAL_COST ويحدث معايرة الانزلاق السعري (Slippage) وتكلفة التنفيذ داخل معاملات ذات إصدار (Versioned Parameters)، ولا يخفض تقدير التكلفة فقط لرفع ترتيب منتج.
20. دورة حياة الاستثمار — INVESTMENT_LIFECYCLE_ENGINE
الأحداث التي تعالج صراحة تشمل MATURITY وCASH_DISTRIBUTION وREDEMPTION_WINDOW وFUND_EXTENSION وFUND_CLOSURE وMERGER_OR_CONVERSION وTRADING_HALT وCORPORATE_ACTION وVALUATION_CHANGE وPRODUCT_TERMS_CHANGE وDEFAULT_OR_DISTRESS.
مسار الحدث:
EVENT_DETECTED → DATA_REFRESH → IMPACT_ASSESSMENT → LIQUIDITY_AND_GOAL_CHECK → POLICY_AND_RISK_CHECK → AUTHORITY_GATE → ACTION → ACCOUNTING_UPDATE → AUDIT.
لا يفترض التجديد أو إعادة الاستثمار تلقائيًا عند الاستحقاق؛ يعاد المنتج إلى أهلية المنتج (Product Eligibility) والملاءمة (Suitability) والتسعير. أي تغير في الشروط يمس السيولة أو الرسوم أو المخاطر أو القفل يعيد احتساب LIQUIDITY_FACTOR وE_min والملاءمة فورًا.
21. الإغلاق والتسييل — CLOSEOUT_AND_LIQUIDATION_ENGINE
يحدد سبب الإغلاق أولًا: GOAL_COMPLETED أو POLICY_EXIT أو RISK_EXIT أو LIQUIDITY_NEED أو PRODUCT_TERMINATION أو USER_ONLY_GOAL_CHANGE أو ENGINE_DEACTIVATION أو BANK_CLOSEOUT.
بعدها يبنى EXIT_PLAN يوازن بين سرعة التحرير، تكلفة الخروج، مخاطر السوق، الضرر على الهدف، قيود الاسترداد، والآثار المحاسبية.
الأولوية للأقل ضررًا لا للأعلى ربحًا أو الخسارة الأكبر. إذا كان البيع الفوري أشد ضررًا وتسمح السياسة، يستخدم STAGED_EXIT ضمن مهلة وحدود واضحة. أما Hard Guard أو السيولة الحرجة فيقدمان الخروج الوقائي بحسب الضرورة.
لا يغلق المحرك محاسبيًا حتى تصبح المراكز صفرًا أو تنقل رسميًا، وتسوى التوزيعات والرسوم والالتزامات المفتوحة، وتنجح ACCOUNTING_RECONCILIATION. أي مبالغ متبقية تعود إلى مركز التخصيص (Allocation Center) ولا تعاد تلقائيًا إلى المصدر السابق.
22. التدقيق وقابلية إعادة الإنتاج
كل قرار مرتبط بالتنفيذ يجب أن يمكن إعادة إنتاجه من البيانات والسياسة والخوارزمية والإصدار المستخدم. يسجل على الأقل: DATA_SNAPSHOT_ID، POLICY_VERSION، ALGORITHM_VERSION، MODEL_VERSION، PARAMETER_VERSION، AUTHORITY_MATRIX_VERSION، البدائل المفحوصة، أسباب الاستبعاد، حدود القرار، نتيجة AUTHORITY_GATE، التنفيذ الفعلي، والنتيجة اللاحقة.
23. القواعد الذهبية للدليل التشغيلي
1) لا تنفيذ قبل بوابة البيانات (Data Gate) والملاءمة والقيود اللازمة.
2) AUTO_AUTHORIZED يذهب إلى طلب تنفيذ من المستخدم، لا إلى تنفيذ مالي من المنصة؛ المراجعة والتصعيد مراحل مشروطة.
3) كل رقم تشغيلي إما مشتق أو محصور أو Versioned Parameter.
4) لا قفز من المبلغ الجديد إلى منتج فردي؛ التخصيص هرمي ومقيّد.
5) E_min اقتصادي ومشتق، وليس رقمًا عامًا ثابتًا.
6) السيولة تحسب حسب الأفق ولا تضاعف الالتزامات المحجوزة.
7) الدفعات مدفوع بالأحداث (Event-Driven) وتبقى داخل حدود اقتصادية وسياسية.
8) التعلم يحسن القرار داخل الحدود ولا يغير السياسة أو الصلاحيات تلقائيًا.
9) إعادة التوازن تبدأ بأقل حركة ممكنة.
10) المحاسبة والتكاليف ودورة الحياة والإغلاق أجزاء أصلية من التشغيل، وليست وظائف لاحقة منفصلة.
11) أي تعارض بين التنفيذ والسياسة يوقف التنفيذ.
12) كل قرار يجب أن يكون قابلًا للتدقيق وإعادة الإنتاج.
21. محركات التشغيل المحدثة
DIGITAL_ASSET_GATE: يصنف الأصل الرقمي ضمن فئة مستقلة ويختبر الشريعة، الحفظ، الجهة، السيولة، التقلب، التركيز، الترابط، ومخاطر التشغيل قبل الانتقال إلى AUTHORITY_GATE.
SHARIA_GATE: بوابة إلزامية تسبق التوصية النهائية. الفشل ينتج RISK_BLOCK.
LEVERAGE_GATE: القيمة الافتراضية BLOCK. لا يسمح بالاقتراض للاستثمار أو الهامش أو المشتقات في النسخة الأساسية.
CONCENTRATION_ENGINE: يحسب حدود التركيز حسب فئة الأصل والمحفظة والهدف وملف المخاطر والسيولة. لا يستخدم 40% كسقف عام موحد.
DRAWDOWN_REVIEW_ENGINE: يحدد Trigger ديناميكيًا حسب تقلب الأصل والفئة والأفق وحساسية المحفظة. الناتج REVIEW_REQUIRED ولا ينفذ بيعًا تلقائيًا.
GOAL_GLIDE_PATH_ENGINE: يعيد ضبط المخاطر المقترحة كلما تغير الوقت للهدف أو تمويله أو سيولته أو Risk Capacity، ويولد توصية تحتاج مسار الصلاحيات والتنفيذ البشري.
LIQUIDATION_PRIORITY_ENGINE: يرتب الأصول للتسييل بدرجة مركبة تشمل زمن الوصول للنقد، الخسارة/التكلفة المتوقعة، الرسوم، الأثر الضريبي/الزكوي عند انطباقه، حماية الهدف، المخاطر وزمن التسوية.
PROTECTED_PORTFOLIO_GATE: يمنع استخدام محفظة هدف حرج قبل استنفاد مصادر أقل ضررًا وفق ترتيب الحماية، إلا إذا فرضت حالة مالية شديدة مسارًا أعلى وموافقة المستخدم.
DISTRIBUTION_REINVESTMENT_ENGINE: يحلل إعادة استثمار التوزيعات والعوائد ويصدر توصية فقط. النقد المحصل يبقى نقدًا حتى تنفيذ المستخدم.
PERFORMANCE_ENGINE: يحسب TWR وMWR/IRR ويحفظ Benchmark المعتمد وإصداره. يقيس العائد بعد الرسوم الفعلية، ويمنع خلط التدفقات الخارجية بأداء مدير الاستثمار.
COST_BASIS_ENGINE: يحفظ Lots الفعلية ويحسب متوسط التكلفة للعرض الأساسي مع دعم الطريقة النظامية المطلوبة عند الحاجة.
FEE_ENGINE: يجمع رسوم المنتجات والمنصات والحفظ والتداول والتسوية وأي تكاليف خروج، ولا ينشئ رسوم إدارة داخلية وهمية لبنك الأصول.
EXTERNAL_MANAGED_PORTFOLIO_GATE: يسمح بترشيح محافظ خارجية متنوعة الأصول ضمن قائمة مزودين معتمدين بعد فحص الشريعة والمخاطر والسيولة والتركيز والرسوم، ثم يعرضها للمستخدم للتنفيذ؛ لا يرتبط بمزود واحد إلزاميًا.
جميع مخرجات هذه المحركات توصيات/اعتمادات خوارزمية ولا تمثل حركة مالية. المسار المالي دائمًا: AUTHORITY_GATE → USER_ACTION_REQUEST → WAITING_USER_CONFIRMATION → EXECUTION_EVIDENCE → VERIFICATION → LEDGER.
نهاية الوثيقة
16. محرك حجم الاستثمار المناسب
لا يحدد حجم الدخول بنسبة ثابتة واحدة. لكل فرصة أو محفظة ثلاثة حدود:
- الحد الأدنى الاقتصادي: أقل مبلغ يجعل الدخول منطقيًا بعد الرسوم وشروط المنتج.
- الحجم المقترح: الحجم الأنسب وفق السيولة والمخاطر والأفق والتنويع.
- الحد الأعلى المسموح: سقف ديناميكي لا يجوز تجاوزه في الحالة الحالية.
يحسب الحد الأعلى بعد مراعاة المال المؤهل الوارد من ملاءة أو المركزي، وسقف المنتج، وحدود المخاطر، وحدود التركيز، والسيولة، والتعرض المجمع القائم. المبلغ المعتمد لا يتجاوز أقل هذه الحدود.
17. محرك التعرض الحقيقي والتركيز
عند الاستثمار في محفظة مدارة، لا يسجل بنك الأصول اسم المحفظة وقيمتها فقط؛ بل يفكك قيمة الاستثمار إلى مكوناتها الفعلية بحسب أحدث إصدار معتمد للمحفظة.
يحفظ التعرض على الأقل حسب:
- السوق.
- فئة الأصل.
- العملة.
- القطاع عند توفره.
- الجهة أو المصدر الاقتصادي.
- الأصل الفردي عند توفر بيانات موثوقة.
مثال تشغيلي: إذا استثمر العقد 40,000 ر.س في محفظة تحتوي 30% أسهم سعودية و25% أمريكية و20% صكوك و15% ذهب و10% أدوات دين، ينشئ المحرك تعرضات تعادل 12,000 و10,000 و8,000 و6,000 و4,000 ر.س على الترتيب.
بعد ذلك يجمع المحرك التعرضات عبر جميع المحافظ والاستثمارات المباشرة. فإذا كانت عدة محافظ مختلفة تحمل سوقًا أو أصلًا أو جهة واحدة، يظهر التركز المجمع حتى لو بدت المحافظ منفصلة ظاهريًا.
المخرجات:
- التعرض حسب الفئة والسوق والعملة والقطاع والجهة.
- نسبة كل تعرض من إجمالي رأس المال الاستثماري.
- التركز الحالي مقابل الحدود المعتمدة.
- التركز الخفي الناتج عن تداخل عدة محافظ.
- أثر الاستثمار المقترح قبل تنفيذه.
18. محرك المخاطر المركبة للعقد
تحسب المخاطر المركبة بترجيح مخاطر كل استثمار بقيمته، مع منع المتوسط من إخفاء تجاوز فردي. لذلك يعمل شرطان معًا:
- قراءة المخاطر الموزونة للعقد كله.
- فحص كل منتج منفردًا مقابل حد العقد وحد المنتج.
إذا بقي المتوسط ضمن الحد لكن منتجًا واحدًا تجاوز السقف المسموح، يعد ذلك تجاوزًا يحتاج مراجعة ولا يسمح بالتوسع الجديد فيه.
19. محرك أفضل مصدر للاسترداد
عند وصول طلب سيولة من ملاءة أو من عقد آخر، يبني بنك الأصول بدائل للاسترداد بدل اختيار أول أصل قابل للبيع.
يقيّم كل مصدر وفق:
- سرعة وصول النقد.
- تكلفة الخروج والرسوم.
- الربح أو الخسارة غير المحققة حاليًا.
- قرب توزيعات أو عوائد قد تتأثر بالخروج.
- أثر البيع على التنويع والتركيز.
- أثره على المخاطر المتبقية.
- جودة الاستثمار على المدى الطويل.
- إمكانية الاسترداد الجزئي بدل الكامل.
المخرج يكون خطة استرداد مفسرة: من أي منتج، كم مبلغًا، زمن الوصول المتوقع، الأثر المالي، البدائل، وأسباب اختيار المسار. لا ينفذ المحرك البيع تلقائيًا.
20. محرك قياس العائد
يفصل النظام بين:
- ارتفاع أو انخفاض القيمة غير المحقق.
- التوزيعات النقدية المستلمة.
- الأرباح التي أعيد استثمارها.
- الربح أو الخسارة المحققة عند البيع.
لا يعامل ارتفاع القيمة السوقية كنقد متاح للسيولة. وعند مقارنة المتوقع بالفعلي يسجل: العائد المتوقع، العائد الفعلي، التوزيعات المتوقعة والمستلمة، والسيولة المتوقعة والفعلية.
21. محرك نضج الاستثمار
مدة النضج خاصية للمنتج ولا تمنع الاسترداد. ويجوز تقسيم المتابعة إلى:
- متابعة مبكرة.
- تقييم نضج أولي.
- مراجعة رئيسية سنوية.
لا يجوز اعتبار ستة أو سبعة أشهر قاعدة عامة لبدء الربح؛ بل تستخدم فقط إذا كانت بيانات المنتج وأسلوب استثماره يدعمانها كنافذة تقييم أولي.
22. محرك المراجعة والتجديد
قبل التجديد السنوي، يجمع بنك الأصول مع ملاءة والمركزي:
- الأداء والعائد مقابل المخاطر.
- السيولة الفعلية عند الحاجة.
- التوزيعات.
- التركز والتعرض الحقيقي.
- التغيرات الجوهرية في المنتج.
- الالتزام بالعقد.
- المخالفات إن وجدت.
- تغير حاجة مالك الأموال.
- البدائل المتاحة حاليًا.
المخرجات المسموحة:
- استمرار مناسب.
- استمرار مع تعديل.
- تخفيض التعرض.
- إعادة توزيع.
- دراسة الخروج.
- إنهاء العقد بعد التسوية.
أي تغيير جوهري في المبلغ أو المخاطر أو المنتجات أو شروط السيولة ينشئ تعديلًا معتمدًا أو إصدارًا جديدًا للعقد، ولا يمحو النسخة السابقة.
23. اختبارات الضغط الاستثمارية وسلوك المحرك
عند هبوط محفظة وارتفاع المخاطر فوق الحد، يمنع أي دخول جديد ويعاد حساب أثر الاحتفاظ والاسترداد الجزئي والكامل، دون تنفيذ بيع تلقائي.
عند طلب سيولة من ملاءة، يجب أن يولد محرك الاسترداد أكثر من بديل عندما تسمح البيانات، ويقارن سرعة الوصول والخسارة والرسوم والتوزيعات القريبة وأثر الخروج على التنويع. لا يجوز اختيار أصل لمجرد أنه الأكثر سيولة إذا كان هناك مسار أقل ضررًا ضمن الموعد المطلوب.
عند تعليق الاسترداد في منتج، يعاد تصنيف سيولته فورًا ولا يحتسب ضمن مصادر السيولة المتاحة. يوقف الاستثمار الجديد فيه ويعاد تقييم العقود المرتبطة.
عند تغير تكوين محفظة، يحفظ إصدار جديد ويعاد احتساب التعرض الحقيقي والمخاطر والتركيز. لا يغير اسم المنتج وحده القرار؛ الخصائص الفعلية هي المرجع.
إذا ظهرت عدة محافظ تحمل السوق أو الأصل أو المصدر نفسه، يجمع المحرك التعرضات قبل إصدار أي توصية جديدة. التعدد الاسمي للمحافظ لا يعد تنويعًا حقيقيًا.
إذا كانت الخسارة داخل النطاق المعتمد ولم توجد مخالفة تفويض، تسجل كخسارة سوقية لا كمخالفة تعاقدية. أما تجاوز حد المخاطر أو استخدام منتج غير معتمد أو مخالفة التوزيع أو السيولة، فينشئ مراجعة تعاقدية ويوقف التوسع.
عند ارتفاع سريع في الأسعار وطلب زيادة الاستثمار، يعاد فحص التركز والسيولة والمخاطر وجودة التوقيت قبل أي توصية بالزيادة.
كل اختبار ضغط يجب أن ينتج: الحالة الحالية، الخيارات المتاحة، الأثر المتوقع لكل خيار، الخيار الموصى به، سبب التوصية، وما إذا كان يلزم تصعيد مركزي أو إجراء من المستخدم.
ملحق تكاملي — التوجيه بين المنظومات والتعلم
1- منظومة الاستثمار والأهداف الذكية هي الطبقة التحليلية الأساسية للملاءمة والأهداف وترتيب البدائل، ويستخدم بنك الأصول نتيجتها ضمن دورة القرار المعتمدة.
2- إذا كان القرار مؤثرًا في السيولة أو الحماية أو المخاطر المركبة، تستدعى منظومة المخاطر المركزية والتحليل الاستباقي قبل التوصية النهائية.
3- إذا كانت هناك التزامات أو ديون قريبة، يستهلك بنك الأصول نتيجة منظومة الالتزامات والديون والتحليل الاستباقي لتحديد القيود، ولا يعيد حساب الالتزام من الصفر.
4- عقد التسليم بين المنظومات يتضمن: نوع التحليل، النتيجة، الثقة، جودة البيانات، آخر تحديث، مراجع السياسة، إصدار النموذج، الآثار العابرة، وحاجة التصعيد.
5- يحتفظ المنسق المركزي للقضية بحالة موحدة من فتح القضية حتى المتابعة والتعلم؛ الواجهة لا تستدعي المحركات بصورة متفرقة خارج هذا المسار.
6- بعد تنفيذ المستخدم والتحقق، تقارن النتيجة الفعلية بالتوقع والفرضية الاستثمارية، وتحدث الذاكرة المالية والتعلم ضمن الحدود المعتمدة.
7- أي نموذج جديد أو تغيير جوهري يمر: دليل → سبب جذري → اختبار خلفي → اختبار ضغط → وضع ظل عند الحاجة → مراجعة حوكمة → إصدار → مراقبة → قبول أو تراجع.
8- لا يجوز أن يؤدي تحسن نموذج تجريبي إلى تغيير سياسة أو حد تركيز أو أهلية أو صلاحية من تلقاء نفسه.
